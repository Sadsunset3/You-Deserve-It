# 《活该》首页、等待室与人物详情体验优化

## 目标

统一首页、等待室与比赛舞台的黑白卷宗视觉；修复 1280×720 下底部内容被裁切；降低轨道人物卡的信息密度，同时保留词条和胜出辩词的完整查看能力。

## 首页

- 删除首页底部整个 `.home-verdict` 黑色“最终问题”区块。
- 首页在“事发经过”内容结束后自然收尾，不保留重复的进入审判按钮。
- 清理对应样式和焦点选择器，避免无效 CSS。

## 等待审判室

- 等待室不使用全黑背景，改为与首页一致的米白卷宗底色、黑色边框和审判红状态强调。
- 顶部保留房间码、阶段、局数、回合和比分。
- 主体改为房间码区加甲乙两个席位区；玩家名称使用高对比正文呈现，并明确标识“你”“对方”“等待加入”“已准备”。
- 准备和开始按钮放入稳定的底部操作区，不漂浮到屏幕角落。

## 比赛舞台布局

- 保持 `100dvh` 且无页面纵向滚动。
- 舞台使用明确的高度分配：顶部 HUD、两条可收缩轨道、底部手牌与操作区。
- 选择阶段压缩列车长资料、人物卡高度和手牌内边距；底部手牌在自身区域横向滚动，不被视口裁切。
- 1280×720 和 1440×900 下都能看到顶部、两条轨道、手牌人物名称及操作按钮。

## 人物卡与详情抽屉

- 轨道人物卡默认显示：人物名称、阵营、两到三行背景摘要、`词条 ×N`、`辩词 ×N`。
- 不在卡面直接展开词条正文和辩词正文。
- 公开人物卡可点击，也支持 Enter/Space；点击后从右侧打开固定详情抽屉。
- 抽屉展示完整人物名称、阵营、背景、全部词条和累计胜出辩词；空列表显示明确空状态。
- 抽屉支持关闭按钮、Escape、遮罩点击，并在打开时获得焦点；关闭后焦点返回原人物卡。
- 抽屉使用米白卷宗视觉，只有标题、危险身份和关键数量使用审判红，不采用黑色整页覆盖。
- 被隐藏的对手人物不能打开抽屉。

## 测试与验收

- 更新首页测试，确认“最终问题”区块不存在。
- 新增人物卡数量摘要和详情抽屉交互测试，包括键盘关闭与空状态。
- 更新等待室测试，确认双方姓名和席位状态可见。
- 运行前端测试、类型检查、lint 和构建。
- 浏览器验收 1280×720 与 1440×900：无纵向滚动、底部操作完整可见、抽屉不被舞台容器裁切。
