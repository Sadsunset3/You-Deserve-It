# 《活该》整场共享手牌与单局流程设计

## 目标

将人物牌和词条牌从“每局重新发放”改为整场比赛共享的有限资源，让玩家必须在房间设置的多局比赛中规划出牌。同时保持每局轨道人物稳定，并清晰展示局数、攻防进度、比分及对手剩余资源。

## 术语

- **整场比赛**：玩家创建房间时设置的全部局数。
- **一局**：从选择人物开始，经过词条阶段、三次攻防、终局压轨和审判的完整周期。
- **攻防**：攻方提交目标与辩词、守方提交答辩、AI 列车长裁决的一次交锋。每局固定三次。

## 发牌与资源生命周期

房间比赛局数只允许设置为 1、3 或 5 局，确保每局都有唯一积分胜者时整场不会出现平局，也不需要在共享手牌耗尽后加赛。

房间开始第一局时，每位玩家一次性获得整场共享手牌：

- 好人人物牌数量等于房间总局数。
- 恶人人物牌数量等于房间总局数。
- 人物牌总数等于房间总局数乘以二，且好人与恶人严格保持 1:1。
- 词条牌数量等于房间总局数乘以二。
- 同一玩家手中的人物牌和词条牌均不得重复。

换局时不重新发牌。已经打出的人物牌和已经使用的词条牌永久离开该玩家本场手牌；未使用词条保留到后续局。

## 单局流程

每局按以下顺序执行：

1. 系统为双方轨道各抽取一名好人人物并放到轨道固定位置。
2. 每位玩家从自己的剩余手牌中选择两张人物牌。两张牌允许任意组合：两张好人、两张恶人或一好一恶。
3. 双方选定的人物进入各自轨道；本局人物阵容至此固定。
4. 玩家可以为轨道上的人物放置任意数量的剩余词条，也可以一张都不使用。使用后的词条从整场手牌中移除。
5. 双方确认词条阶段结束后，进行三次攻防。攻守方逐次互换，人物卡和已附加内容在三次攻防期间保持不变。
6. 三次攻防完成后，AI 列车长综合双方轨道人物、背景、词条和六段辩词作出终局压轨裁决。
7. 显示双方可见的审判总结，幸存方获得一分。
8. 若尚未达到房间总局数，进入下一局并继续使用剩余手牌；否则按积分判定整场胜负。

## 状态与数据边界

- 房间在第一局开始时创建一次 `hands`，后续局沿用。
- 人物牌和词条牌通过整场级已使用 ID 集合进行消费，不在换局时清空。
- 每局只清空轨道选择、人物词条映射、辩词、三次攻防记录、终局裁决和审判结果。
- 系统自动抽取的人物不属于任一玩家手牌，不影响玩家的好恶牌剩余数。
- 公共房间视图只向玩家暴露对手各类手牌的数量，不泄露具体卡面。

## HUD 与手牌界面

舞台 HUD 持续显示：

- 当前局数 / 房间总局数；
- 当前攻防次数 / 3；
- 双方比分；
- 对手剩余好人牌数量；
- 对手剩余恶人牌数量；
- 对手剩余词条牌数量。

自己手中的人物卡完整横向展开，不使用负间距叠放或宽度压缩。空间不足时手牌区域独立横向滚动，页面仍可纵向滚动。拖出人物牌后，该牌立即从原位消失，其余牌平滑向前补齐；无效放置或取消拖拽时恢复原顺序。

## 异常与自动推进

- 服务端拒绝重复使用、并非本人持有或已被消费的牌。
- 每局必须正好选中两张人物牌才能进入词条阶段。
- 词条阶段允许零张词条。
- 超时自动选择时，只能从该玩家整场尚未使用的人物牌中补足两张。
- 断线、投降和超时沿用现有处理规则，不重新发牌或恢复已消费资源。

## 验证

- 单元测试验证不同房间局数下，人物牌总量、好恶 1:1 和词条牌总量。
- 房间流程测试验证换局不重新发牌、未用词条跨局保留、已用资源不可复用。
- 流程测试验证每局两张人物、任意好恶组合、固定三次攻防后才进入终局。
- 公共视图测试验证仅暴露对手好人、恶人和词条的剩余数量。
- Web 测试验证 HUD 文案、展开手牌、横向滚动和拖拽补位行为。
