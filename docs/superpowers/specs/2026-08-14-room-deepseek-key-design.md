# 房间级 DeepSeek Key 设计

## 目标

创建审判室前，房主必须输入并成功测试一个 DeepSeek API Key。该 Key 只供当前房间的回合裁决、轨道裁决和赛后审判使用；整场比赛结束、投降结束、房间过期或房间被清理时立即删除。

## 安全边界

- Key 仅由创建房间的玩家输入。
- 前端只在测试连接和创建房间请求中发送 Key，不写入浏览器存储。
- 服务端仅在内存中按房间码保存 Key，不写入房间快照、SQLite、日志、RoomView 或 Socket 消息。
- 加入房间的玩家不需要也不能读取 Key。
- 服务端重启后内存 Key 消失；旧房间不得回退使用环境变量中的固定 Key。
- 删除当前 `.env` 中的 `DEEPSEEK_API_KEY`，生产裁决不再读取 `DEEPSEEK_API_KEY` 或 `OPENAI_API_KEY`。

## 接口与数据流

新增 `POST /api/ai/test-key`，请求体包含 `apiKey`。服务端使用既有 DeepSeek Base URL 和模型发起最小连接测试，只返回成功或经过脱敏的错误，不记录请求体。

`POST /api/rooms` 增加必填 `apiKey`。服务端创建房间后，将 Key 写入独立的内存 Key 仓库。AI 裁决发生时，按房间码取 Key，并为该次调用创建或获取房间级网关。RoomManager 的持久化快照不包含 Key。

前端建房区新增密码输入框与“测试连接”按钮。只有昵称、房间配置、非空 Key 且最近一次针对当前输入值的测试成功时，才允许创建房间；Key 一旦修改，测试状态立即失效。加入房间流程不显示 Key 输入。

## 生命周期与错误处理

- 正常整场结束：删除房间 Key。
- 任一方投降并使比赛结束：删除房间 Key。
- 房间过期或清理：同步删除房间 Key。
- 服务端重启导致旧房间缺少 Key：裁决请求返回明确的“房间 DeepSeek Key 已失效，请重新建房”错误，不使用固定环境 Key。
- 测试失败：展示可理解的连接失败提示，不回显 Key，不允许创建房间。

## 测试

- 合同测试：创建房间必须包含合法非空 Key。
- AI 客户端测试：显式 Key 生效，环境变量 Key 不再作为生产回退；连接测试成功与失败均被正确转换。
- 服务端测试：测试 Key 接口、建房绑定、不同房间隔离、裁决使用对应 Key、比赛结束和投降后删除、快照不含 Key。
- 前端测试：建房前必须输入并测试；修改 Key 后失效；成功测试后提交 Key；加入模式不要求 Key。
- 最终运行全部测试、类型检查、Lint、生产构建，并进行浏览器建房交互验证。
