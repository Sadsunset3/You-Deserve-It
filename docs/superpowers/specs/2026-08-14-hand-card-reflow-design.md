# 手牌拖动抽离与扑克牌补位动画

## 目标

修复人物卡开始拖动后仍留在手牌原位的问题。拖动中的人物卡只显示指针浮层，手牌队列立即移除原卡，后续卡片像扑克牌一样向前补齐。

## 状态与顺序

- `dragState.sourceId` 存在时，手牌渲染列表临时排除该人物卡。
- 浮动拖拽层继续使用完整人物卡数据跟随指针，不影响当前拖放命中逻辑。
- 不修改服务端手牌数组；原始数组始终作为稳定排序来源。
- 成功放入人物槽位后，该卡由本地 `slots` 状态继续排除在手牌之外，补位后的顺序保持不变。
- 松手落在手牌、无效区域，或者拖动因 `pointercancel`、窗口失焦、阶段变化而取消时，该卡按原始数组索引重新出现。
- 取消复原不把卡片追加到末尾，也不改变其他卡片的相对顺序。

## 动画

- 使用原生 FLIP 布局动画，不新增运行时依赖。
- 手牌卡片使用人物 ID 作为稳定键，并暴露可查询的数据属性。
- 每次可见手牌 ID 顺序变化前记录卡片矩形，React 完成布局后读取新矩形。
- 对仍存在的卡片从旧位置到新位置施加反向位移，再用 `transform 220ms cubic-bezier(.16,1,.3,1)` 回到零位移。
- 被拖卡取消后重新插入时，从相邻卡片方向以短距离位移和透明度变化进入，形成“让位后插回”的效果。
- 只动画 `transform` 和 `opacity`，避免动画 `left`、`width` 或 `margin`。
- 动画中的卡片使用局部 `will-change: transform`，完成后清除行内变换。
- `prefers-reduced-motion: reduce` 下立即更新布局，不播放补位或插回过渡。

## 交互边界

- 点击选择人物的现有行为不变；只有实际进入 `dragState` 后才临时抽离手牌卡片。
- 轨道槽位中的人物拖动沿用同一浮层，但不会错误过滤手牌中其他人物。
- 拖动期间手牌容器仍保留 `data-drop-type="hand"`，允许把轨道人物拖回手牌。
- 锁定选择或服务器确认后不播放多余的回插动画。
- 组件卸载时取消未完成动画和帧回调，不操作已卸载节点。

## 组件边界

- `SelectionTray` 负责计算可见手牌列表和保存手牌容器引用。
- 新增专用布局动画 Hook，输入有序人物 ID 列表与容器引用，只负责测量和 FLIP 动画，不读取房间业务状态。
- `usePointerDrag` 保持现有指针监听、命中检测和取消语义，不把视觉动画耦合进底层拖拽 Hook。
- `CharacterCard` 仅增加人物 ID 数据属性透传能力，不管理手牌顺序。

## 测试与验收

- 指针按下人物卡后，原手牌中该人物立即消失，浮动层仍展示该人物。
- 后续卡片保持原相对顺序并获得补位动画状态。
- 成功放入槽位后，被拖人物不回到手牌。
- 无效落点、`pointercancel` 和窗口失焦后，被拖人物恢复到原始索引。
- 系统减少动态效果时不创建过渡动画，但拖放结果一致。
- 运行前端测试、类型检查、Lint 和构建。
- 浏览器验证 1280×720：拖动第一张和中间人物卡时均无原地副本，补位平滑，取消后正确插回。
