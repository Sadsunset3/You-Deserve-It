# 《活该》权威攻防对局重构设计

## 目标

把现有分散在页面下方的攻防表单重构为服务端权威、单屏弹窗驱动的三回合道德辩论。每局产生三次攻防、六段玩家辩词，之后由 DeepSeek 依次完成回合裁决、最终压轨和黑暗哲学审判；达到房间设置局数后按积分决出整场胜者。

## 已确认规则

- 游戏舞台固定在一个 `100dvh` 视口内，比赛期间禁止页面纵向滚动；正式桌面基准仍为 1280×720 及以上。
- 每回合开始时，服务端分别为甲乙轨道随机抽取一名不在双方手牌中的好人并公开锁定。玩家再各选择两人，因此每条轨道恰好三人。
- 第一回合随机决定攻方，第二、第三回合严格交换攻守；每局共三次攻防。
- 每次攻防由一段攻击和一段防守组成，因此每局保留六段原始玩家辩词。
- 攻方在弹窗中选择对方轨道上的一名人物并提交攻击；守方在攻击提交前只看见等待状态，提交后在弹窗中看见完整目标档案和攻击文本，再提交防守。
- DeepSeek 根据列车长完整人设、目标人物名称与背景、全部词条、历史胜出辩词和本轮双方辩词判断本轮赢家。只有胜方辩词写入目标人物的累计论据。
- 第三次攻防结束后，DeepSeek 根据列车长人设和两边全部六名人物的名称、背景、词条、累计胜出辩词决定压死哪条轨道。幸存方本局加 1 分。
- 最终压轨后进入双方可见的黑暗审判。DeepSeek 接收六段原始辩词、三次目标选择、三轮判断和最终压轨决定，从人性、哲学、自利与论证矛盾等角度生成尖锐、反讽但不辱骂玩家的共同评议。
- DeepSeek 超时、限流、未配置或返回非法结构时，服务端立即使用确定性本地备用裁决，并在结果中标记 `fallback: true`，不阻塞房间。
- 比赛中阶段常驻“投降并退出”。二次确认后服务端立即结束整场比赛，对手直接获胜并广播结果。
- 审判结束后双方准备进入下一局；完成设置局数后积分高者获胜。平分时追加一局，延续现有规则。

## 服务端状态机

```text
waiting
  -> selecting
  -> traits
  -> attack-input
  -> defense-input
  -> round-adjudicating
  -> round-result
     -> attack-input             (第 1、2 回合，攻守互换)
     -> track-adjudicating       (第 3 回合)
  -> judgment-generating
  -> judgment
     -> between-games            (尚未完成设置局数或比分平局)
     -> match-end                (整场结束)
  -> selecting                   (双方下一局准备完成)
```

同一阶段针对双方生成不同视图。例如 `attack-input` 中，攻方得到可编辑攻击弹窗，守方只得到等待弹窗；服务器不接受非当前席位提交的命令。

## 核心数据

- `automaticCharacters`: 当前回合甲乙两边自动抽取的好人 ID。
- `roundAttacker`: 当前回合攻方席位。
- `roundRecords`: 每轮的攻方、守方、目标人物、原始攻击、原始防守和回合裁决。
- `characterArguments`: 仅保存胜出辩词，并记录所属轮次、角色和玩家席位。
- `trackVerdict`: 被压轨道、幸存轨道、理由、决定因素和备用裁决标记。
- `judgment`: 标题、共同总结、甲方评议、乙方评议、列车长自我矛盾评议、留给双方的问题和备用标记。
- `nextGameReady`: 审判结束后双方是否确认进入下一局。

## AI 边界

AI 网关提供三个强类型方法：

```ts
decideRound(input: RoundDecisionInput): Promise<RoundVerdict>
decideTrack(input: TrackDecisionInput): Promise<TrackVerdict>
judgeMatch(input: JudgmentInput): Promise<PhilosophyJudgment>
```

每个方法使用独立 Zod 响应结构、最多三次解析尝试和独立本地 fallback。Prompt 只允许返回 JSON。服务端在发给 AI 之前构建完整、无遗漏的输入对象，不让前端拼接 Prompt。

## 单屏界面

- 顶部：房间、局数、回合、比分、倒计时、连接状态、投降入口。
- 左上：列车长人设与本局规则；只显示最关键的三行，详情可展开弹窗。
- 中部：两条轨道，每边三张紧凑人物卡；名称直接作为头像，卡面显示身份、短背景和累计胜出论据数量。
- 底部：只保留阶段提示和必要的选人/贴词条托盘。攻防输入不再出现在舞台下方。
- 弹窗：攻击、等待、防守、回合裁决均使用同一焦点管理良好的模态层；ESC 不能关闭不可逆提交弹窗。
- 黑暗审判：整屏切换为黑色，审判红作为唯一高饱和色，展示压轨结果与共同评议。减弱动画时直接切换，无闪烁、震动或大幅位移。

## 错误与恢复

- 所有写命令携带 `commandId` 和 `expectedVersion`，保持幂等与版本冲突保护。
- 刷新后根据服务端 phase 恢复对应弹窗，不依赖客户端临时步骤。
- 攻击或防守超时由服务端写入空辩词并继续裁决；AI 阶段不接受玩家命令。
- 旧房间快照缺少新字段时，在加载时执行内存迁移并持久化默认值，避免本地 SQLite 现有房间导致启动失败。

## 验收标准

- 1280×720 和 1440×900 下比赛舞台 `scrollHeight <= clientHeight`。
- 每边始终一名自动好人加两名玩家人物，且自动人物不与双方手牌或本局已用人物重复。
- 三轮攻守席位严格交替，共保存六段原始辩词。
- 非当前玩家、重复命令、旧版本命令和非法目标均被拒绝。
- 三种 AI 调用均覆盖成功、非法 JSON、超时/抛错和未配置场景。
- 胜出辩词准确附加到目标人物；最终压轨加分、审判共享、下一局与整场结束流程正确。
- 投降立即结束整场并判对手获胜。
- 全量 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm build` 通过。
