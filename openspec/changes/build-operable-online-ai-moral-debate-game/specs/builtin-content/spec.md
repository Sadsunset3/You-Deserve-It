## ADDED Requirements

### Requirement: 内置人物牌库
系统 MUST 随应用提供经过审查的人物牌库，每个人物包含唯一 ID、名称、背景、`good` 或 `evil` 分类以及本地默认卡面引用。

#### Scenario: 启动校验人物内容
- **WHEN** 服务启动并加载人物牌库
- **THEN** 系统验证字段、唯一 ID、分类、卡面资源存在性和满足双人发牌的最低数量，不合法时拒绝就绪

### Requirement: 内置词条牌库
系统 MUST 随应用提供经过审查的词条牌库，每个词条包含唯一 ID、正文、标签和仅供降级规则使用的极性元数据。

#### Scenario: 玩家查看词条
- **WHEN** 系统向玩家发放词条
- **THEN** 客户端只展示正文和公开标签，不展示内部降级权重

### Requirement: 内置列车长人格
每个内置列车长人格 MUST 明确规定价值判断规则，而非仅描述气质，并可同时供 AI 提示和本地降级裁决使用。

#### Scenario: 选择人格
- **WHEN** 新一局开始
- **THEN** 系统从合法内置人格中随机选择一个并在该局所有裁决中保持不变

### Requirement: 内容只读
MVP MUST NOT 提供人物、卡面、词条或人格的上传、创建、编辑、删除和管理接口。

#### Scenario: 玩家端能力边界
- **WHEN** 玩家使用任意正常页面或 API
- **THEN** 系统不展示或接受自定义卡面与牌库内容
